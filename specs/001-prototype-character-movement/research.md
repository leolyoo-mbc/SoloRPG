# Research: 3인칭 이동 프로토타입 설계 결정

| 결정 | 근거 | 검토한 대안 |
| --- | --- | --- |
| 기존 `Player/Move`와 `Player/Look` 사용 | 입력 에셋에 이동과 포인터 델타, 오른쪽 스틱 바인딩이 이미 있다. 기존 Move처럼 Look 액션을 복제해 활성화·비활성화 수명 주기를 관리한다. 활성 컨트롤의 기기를 기준으로 마우스와 게임패드 입력을 구분한다. | 새 액션 에셋을 만들면 기존 바인딩을 중복 관리한다. |
| 마우스 델타와 스틱 크기를 각각 변환 | 포인터 델타는 해당 입력 업데이트 동안의 움직임이므로 각도/픽셀을 적용한다. 스틱은 방향과 크기를 유지하므로 각도/초와 프레임 시간을 적용한다. | 입력 종류에 상관없이 프레임 시간을 곱하면 마우스 감도가 프레임 속도에 영향을 받는다. |
| 시선 수평 회전을 같은 프레임의 이동에 사용 | 시선 입력 → 캐릭터 회전 및 이동 → 카메라 위치 갱신 순으로 처리하면 시선을 돌리는 동시에 W를 눌러도 그 프레임의 새 방향으로 움직인다. 기존 경계 검사는 회전된 월드 이동 벡터에 적용한다. | 카메라 Transform의 전체 회전을 직접 쓰면 상하 시선이 이동에 영향을 준다. |
| 가까운 오른쪽 어깨 시점과 제한된 상하 각도 | 캡슐 옆으로 약간 비켜 앞쪽 바닥을 보여주고, 등 표식으로 캐릭터의 방향을 확인한다. 평평한 테스트 씬에서 초기 거리와 각도는 카메라가 바닥 위에 있도록 잡는다. | 고정 각도의 높은 시점에서는 바닥이 화면 대부분을 차지한다. |
| Game 뷰 클릭으로 마우스 잠금 | 마우스를 계속 돌릴 수 있고 Esc로 에디터 조작에 복귀할 수 있다. | 마우스를 자유롭게 두면 창 가장자리에서 시선을 계속 돌리기 어렵다. |
